## 任务描述

搭建 Superteam 全部包共用的工程基座：pnpm workspace、TypeScript 基座配置、vitest 全局测试配置、根脚本。对应 PRD §6「测试/可观测」的工程前提，是所有模块（M0-M6）的公共依赖。

- [x] 12 个包（core/infra/data/gitprov/knowledge/tasks/radar/distiller/mcp/daemon/server/web）骨架就位，内部引用走 `workspace:*`

## 技术路线

- pnpm workspace（`packages/*`），pnpm 12.3.4
- TypeScript 5.9，`moduleResolution: "bundler"`，全包 `noEmit`：**不引入构建编排**，各包 `exports` 直接指向 `src/index.ts`，运行时用 tsx、测试用 vitest（esbuild 转换）
- 单根 `vitest.config.ts`，glob 覆盖 `packages/*/src/**/*.test.ts`

## 原理

包间引用不经过编译产物：包 A import `@superteam/core` 时，pnpm 的 symlink 将其解析到 `packages/core`，其 `exports["."]` 指向 TS 源文件；tsx/vitest 内部的 esbuild 直接转换 TS。好处是零构建编排、改动即时生效；代价是不产出独立 npm 包（本项目为内部应用，可接受）。

## 报错与解决

1. **报错**：`pnpm install` 出现 `Ignored build scripts: esbuild@0.28.2`，交互式 `pnpm approve-builds` 在非 TTY 下报 `IO error: not a terminal`。
   **解决**：pnpm 12 支持在 `pnpm-workspace.yaml` 声明 `allowBuilds: { esbuild: true, better-sqlite3: true }`（首次尝试 `onlyBuiltDependencies` 列表写法未生效，pnpm 自动写入了 `allowBuilds` 占位提示真实字段名）；改后删除 node_modules 全量重装，无告警。

2. **报错**：`rm -rf packages/*/node_modules` 在 zsh 下报 `no matches found`（glob 无匹配即报错）。
   **解决**：改用 `find packages -name node_modules -type d -exec rm -rf {} +`。
