# ROADMAP — 优化建议与演进路线

> 基于 MVP 全量建设、43 项 E2E 全功能扫描、以及真实项目（53 任务 / 11 成员的智能体测评平台）接入实践的观察。
> 总体判断：**骨架（状态机/事件流/检索/agent 接入）是对的；最缺的不是更多功能，而是「与真实世界合拢」的那几条线——仓库、IM、多台机器的现实。**

## P0 —— 决定「团队能不能真用起来」

### 1. Gitee PR 回写，打通交付闭环
daemon 把任务推进到 waiting_review 就停了，但真实交付终点是 **Gitee PR 合入**。任务是任务、PR 是 PR，两边靠人肉对齐——正是要消灭的「人肉网线」。实现 GitProvider 的 Gitee 实现：daemon 提交分支后自动开 PR（引用任务 ID），PR webhook 回写任务状态（merge → approve / close → 打回），评审意见结构化注入 agent 下一轮 prompt。

### 2. 认领的原子性（潜伏的真 bug）
两个 daemon 同时 tick 会认领**同一个**任务：当前是「读列表 → 校验 → 写回」，无条件更新。解法很轻：`UPDATE tasks SET status='claimed' WHERE id=? AND status='draft'`，影响行数为 0 换下一个。单测 + 并发测试钉死。

### 3. 依赖图「可执行化」：ready 队列 + DAG 全景
84 条依赖边是最值钱的资产，但目前只能在详情侧栏看。①看板增加「**现在可做**」视图——上游全 done 的任务按拓扑排序（每个人打开就知道下一步做什么）；②DAG 全景图（模块分泳道、关键路径高亮）。

### 4. 飞书双向入口
现在只有 webhook 出口。指令的**入口**才是止痛药：群里 @共工 一句话 → LLM 解析成带 DoD 的任务草案 → 看板草稿区待人确认。配合 digest 推送，飞书从「信息黑洞」变成「共工的两个触角之一」。

### 5. 知识库「引用而非复制」
接入真实项目时把对方仓库的 AGENTS.md **快照**了一份——从今天起与原文漂移。正确姿势：知识库存「索引 + 指针」（仓库路径 + commit），MCP read 按指针**实时读仓库**。不制造第二个事实源。

## P1 —— 真实团队用一个月后一定会要的

### 6. 分布式冲突雷达
雷达只扫服务器本机 worktree——真实团队每人一台机器。把 sweep 下放到 daemon：每个 daemon 扫自己的 worktree，把「任务 → 改动文件清单」作为心跳上报（仍是声明式摘要，不越隐私边界），服务端汇总求交。

### 7. agent 执行的进度流与预算
coding 状态期间看板是黑盒。解析 Claude Code stream-json 的工具调用事件作为声明式进度上报（只报动作类型，不碰内容）。同时加执行超时 + token 预算 + 失败重试上限（MAST 研究里「预算失控」「卡死任务」都是这一层缺失）。

### 8. 个性化 digest
按人聚合：我的任务变化 + 依赖我的下游动态 + 我模块相关的冲突/新知识。信息过滤是「对抗轰炸」的最后一公里。

### 9. 混合检索
FTS5 是词面匹配，「为什么这个接口要幂等」这类语义问题命中率有限。加本地 embedding / GLM embedding API 的向量召回，与词面召回混合排序。卡片过百后必需。

### 10. 权限长出牙齿
role（lead/member）现在无实质约束——任何人可验收任何任务。至少：只有 assignee 和 lead 能迁移任务；propose 到 specs/ 需 lead 审。吃自己的狗粮（平台的 P0-01 模块就是「身份与权限」）。

## P2 —— 看清楚了再做

- **A2A 联邦**：等生态成熟再把「跨人 agent 委派」从窄接口升级为协议级互联，现在做是过度设计；
- **Postgres 多实例**：50 人内 SQLite 够用，schema 已兼容，不动；
- **UI 组件化重构**：先按人/模块过滤、分组折叠续命，交互形态稳定后再换组件库。

## 战略性观察

真实接入的 AEP 项目本身是「智能体评测平台」，而它正用共工管理自己的建设——**共工可以反向借用 AEP 的领域方法论评测自己**：把每个 daemon 任务的产出当作被测对象，用 AEP 的评分规则（确定性规则 + 受控大模型评分）给 agent 产出打分，评分回写任务卡辅助验收。两个平台互相成就：AEP 得到天然真实场景，共工得到现成的质量评估语义。

## 若只做三件事

**②认领原子性（半天，堵住真 bug）→ ①PR 回写（两三天，闭环真实流程）→ ③ready 队列 + DAG 视图（一两天，把分工表变成每个人每天打开就能用的东西）**
